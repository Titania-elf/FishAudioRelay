# Fish Audio 私人本机中转

让本机 SillyTavern 的 **ST-iPhonie 插件**使用自己的 Fish Audio 网页订阅。通过常用 Chrome 中已登录的 Fish 标签页生成语音，登录凭据留在 Fish 页面，无需复制 Cookie 或填写 Fish API Key。需要 Windows 与 Node.js 22 或更新版本。

旧版 API Key 接入仍可从管理页选择，按 API 余额计费。两种模式互不自动回退。新配置默认使用网页订阅；已有配置可以在管理页改为「网页订阅」。

## 启动与配置

1. 双击 `Start.bat`（只有这台电脑用）或 `Start-手机可用.bat`（手机也要用），保持服务窗口开启。手机可用模式首次启动时 Windows 会询问是否允许 `node.exe` 联网，请勾选「专用网络」并允许，否则手机连不上。
2. 在浏览器打开 **http://127.0.0.1:17863/**。
3. 选择 **网页订阅**，将「连接 Fish 订阅」按钮拖到 Chrome 书签栏（Ctrl+Shift+B 显示书签栏）。
4. 切换到常用 Chrome 中已登录的 [Fish 文字转语音页面](https://fish.audio/app/text-to-speech)，点击该书签并允许打开本机连接窗口。个人账号的团队空间可以直接使用。保持 Fish 标签页和连接窗口打开，连接窗口可以最小化。
5. 配置模型和音色：默认模型 `s2.1-pro`；音色别名例如 `default`、`alice`，Reference ID 填音色页面地址中的 32 位 ID。网页订阅模式必须填写固定音色 ID。选择默认音色，点击「保存配置」。
6. 点击「读取订阅额度」或「生成试听」。管理页显示连接状态、剩余额度及 API 余额；试听和酒馆朗读走同一条网页订阅流程。

正式中转使用 **17863** 端口。此前 **17865** 上的测试书签仅用于诊断，请从正式管理页保存新的「连接 Fish 订阅」书签。正式书签在服务重启后仍可使用，端口或中转 KEY 更换后需更新书签。刷新 Fish 网页后要重新点击书签；仅重启本机服务时，可点击连接窗口的「重新连接」。本次加入 Drama 3 升级了书签脚本（版本 2），旧书签会提示更新：请刷新管理页、重新拖动保存书签，再到 Fish 标签页点击新书签。

## 在手机酒馆里使用

1. 电脑上双击 `Start-手机可用.bat`（不是 `Start.bat`），允许防火墙的「专用网络」。
2. 管理页「接入 ST-iPhonie」会多出**手机酒馆中转地址**，形如 `http://192.168.2.5:17863`，点「复制」。
3. 手机浏览器打开酒馆，地址用电脑的局域网 IP（例如 `http://192.168.2.5:8000`），不能是 `127.0.0.1`；酒馆需已开启局域网访问。
4. ST-iPhonie 里把**中转地址**换成刚复制的那个；中转 KEY、模型、音色、格式都照旧不变。电脑上的酒馆仍填 `http://127.0.0.1:17863`，两者互不影响。
5. 手机与本机连同一个 Wi-Fi。Fish 标签页和连接窗口照旧在电脑的 Chrome 里开着，手机侧不需要登录 Fish。

手机同样只能朗读，不能打开管理页、试听或连接 Fish；每次朗读也会占用网页订阅额度。

## ST-iPhonie 设置

在这台电脑用 `http://localhost:8000` 或 `http://127.0.0.1:8000` 打开酒馆，然后打开 **ST-iPhonie → 引擎 → Fish Audio**。已检查更新后的 0.7.99 版，插件自带所需中转设置，并已将 Drama 3 的模型名更新为 `drama-3`，不需要修改插件源码。

| 插件字段 | 填写内容 |
| --- | --- |
| 中转地址 | `http://127.0.0.1:17863` |
| 中转接口格式 | **OpenAI 格式（/v1/audio/speech）** |
| API Key | 管理页提供的「中转专用 KEY」 |
| 模型 | `s2.1-pro` 或 `drama-3`，均已通过当前账号的真实订阅生成验证 |
| 音频格式 | `mp3` |
| 语速 | `1`；Fish 支持 `0.5–2` |

先保存中转专用 KEY，再填写中转地址并点击「使用中转」或「保存中转」。保存或「测试连接」会自动识别 OpenAI 格式，也可手动选择。该测试发送空请求：`/compat/v1/audio/speech` 返回 404，随后 `/v1/audio/speech` 返回 400；插件显示「合成接口通了」就是正确结果，测试不会生成音频或消耗订阅额度。这个测试只确认本机接口与 KEY，Fish 是否已连接仍以管理页为准。

在插件的**角色设置**中选择 Fish Audio，把角色的「音色」设为 Fish 音色页面地址中的 **32 位音色 ID**。可以复制管理页的「默认音色 ID」，也可以给不同角色填写各自的 ID，无需逐个在中转添加别名。已有别名映射仍可使用。最后在插件里试听一句。

此接法支持文本、文本内的情绪标签、音色 ID、模型和语速。插件中不提供音色列表或余额查询，套餐余额在中转管理页查看。请清空参考音频设置；温度、采样率等其他 Fish 参数不会由插件的 OpenAI 请求传入。Fish 引擎的密钥列表只保留这个中转 KEY 即可。

网页订阅模式把酒馆文本、音色和语速交给已连接的 Fish 标签页，沿用网页的团队及工作区设置，通过 `/task` 生成 MP3。音频完整生成后返回酒馆，暂未实现边生成边返回。目前可选择 `s2.1-pro`、`drama-3`、`s2-pro`、`s1`，其中 S2.1 Pro 与 Drama 3 已完成当前账号的真实订阅验证。Drama 3 按 Fish 网页的 `backend: "drama-3"` 接入，单次仍为一个音色；已使用 ST-iPhonie 0.7.99 的请求代码收到 MP3，并确认 Plus 额度减少、API 余额未变。插件中须保持 OpenAI 格式，才能沿用本地网页订阅流程。

SillyTavern 自带的 OpenAI Compatible TTS 也可使用完整接口 `http://127.0.0.1:17863/v1/audio/speech`，同一个中转 KEY，以及管理页保存的音色别名。`tts-1` / `tts-1-hd` 自动映射为管理页保存的 Fish 模型。

## 运行范围与存储

- 默认（`Start.bat`）中转只监听 `127.0.0.1`，适用于酒馆服务和中转运行在同一台电脑的情况。本机 Docker 内的酒馆不能用容器的 `127.0.0.1` 直接访问它。
- `Start-手机可用.bat` 让中转额外接受同一局域网内的请求，并把手机要填的地址打印到服务窗口。手机与本机需连同一个 Wi-Fi；管理页仍只允许本机打开，手机拿不到中转 KEY 以外的内容。
- ST-iPhonie 由浏览器直接请求中转，所以酒馆页面在哪个设备上打开，就由哪台设备发起请求。电脑上填 `http://127.0.0.1:17863`；手机上必须填本机局域网 IP（形如 `http://192.168.2.5:17863`，可在管理页「手机酒馆中转地址」复制），填 `127.0.0.1` 只会指向手机自己。其他设备或远程部署需要另行配置网络接入。
- 跨域允许 `http://localhost:8000` 与 `http://127.0.0.1:8000`，开启手机可用模式后还包括酒馆所用的局域网地址，仅限语音、模型列表及协议探测路径，生成仍需中转 KEY。管理、预览和 Fish 连接接口不对任何外部来源开放，手机也无法打开；其他域名可用环境变量 `FISH_RELAY_ORIGINS` 添加。
- 电脑需要开机、保持中转和两个浏览器页面运行；Fish 网络请求由 Chrome 发出，可沿用浏览器的网络环境。语音仍由 Fish Audio 云端生成。
- 中转 KEY（以及可选的 API Key）使用 Windows DPAPI 当前用户加密，保存于 `data/config.json`；网页登录令牌不传回本机服务。复制配置到另一 Windows 账号或电脑无法直接解密，请重新配置。
- `data/` 目录还包含音色配置和浏览器连接状态，已列入 `.gitignore`。分享源码时请直接通过 Git 仓库或只打包源码文件，**不要**把整个 `data/` 目录一起压缩上传。
- 管理页面只供本机访问，不使用外部脚本；API 修改需页面会话令牌，酒馆生成需中转 KEY。日志只记录生成编号、耗时及结果，不记录 KEY、朗读文本或音频。
- 生成音频不保存到服务器磁盘；试听时可手动下载 MP3。网页订阅每段最多 **1000 字**，逐段生成，最多接收 6 个未完成请求（含正在生成的一段），含排队超时 180 秒，单段音频最大 12 MB。ST-iPhonie 的合成请求最长等待 120 秒，请使用较短的台词并减少同时生成，避免排队超时。API 模式仍为 10,000 字、2 个并发、120 秒。
- 断线、验证失败或额度不足会返回错误，不会自动重试或回退到 API；请求取消会通知网页中止，但已经产生的上游费用是否退还由 Fish 决定。生成前检查订阅额度，生成后更新余额摘要；如果检测到 API 余额减少，会保留本次音频并停止后续自动朗读。
- 关闭 `Start.bat` 的服务窗口或按 Ctrl+C 可停止服务。未设置开机自动启动。

若首次启动由后台方式运行，可用 PowerShell 查询仅此服务的进程并停止：

```powershell
Get-CimInstance Win32_Process -Filter "Name = 'node.exe'" |
  Where-Object { $_.CommandLine -like '*FishAudioRelay*server.js*' } |
  ForEach-Object { Stop-Process -Id $_.ProcessId }
```

## 常见问题

- **中转 KEY 无效**：酒馆中请填「中转专用 KEY」，Fish Audio 的真实 KEY 在管理页保存。
- **等待连接 Fish 网页**：在已登录的 Fish 标签页点击正式中转书签，允许弹窗，并保持两个页面打开。
- **尚未配置 Fish KEY**：这是 API 模式提示。如需使用订阅，请改选网页订阅并保存。
- **Fish 401/403**：在 Fish 页面重新登录、完成验证，或检查音色权限，再重新连接。
- **Fish 402**：检查当前模式对应的订阅额度或 API 余额。
- **Fish 400/422**：检查模型名、音色 Reference ID、文本长度及语速。
- **Fish 429**：减少并行生成或稍后重试。
- **连接失败**：先确认 Fish 网页能正常生成、两个页面仍打开。API 模式还需要 Node.js 自身能访问 Fish API。
- **ST-iPhonie 显示跨域或连接错误**：确认中转已启动，酒馆由本机浏览器从 `http://localhost:8000` 或 `http://127.0.0.1:8000` 打开，中转地址填写根地址，协议为 OpenAI 格式。
- **手机酒馆连不上或提示跨域**：确认双击的是 `Start-手机可用.bat`，手机与本机在同一 Wi-Fi，中转地址填管理页复制的局域网 IP 而不是 `127.0.0.1`，并已在防火墙里允许 `node.exe` 使用专用网络。
- **端口已占用**：先打开管理地址，已有服务正在运行时不用再启动。若启动时提示「端口 17863 上已经有一个中转在运行」，说明上一个服务窗口没有关闭，请先关掉它再启动；同时开两个会出现管理页正常但手机一律 503 的情况。需更换端口时，在 PowerShell 中运行 `$env:FISH_RELAY_PORT = '17864'` 然后 `node server.js`，并将酒馆 Endpoint 改为新端口。管理页也会显示实际端口。
- **不想用批处理开手机模式**：在 PowerShell 中运行 `$env:FISH_RELAY_LAN = '1'` 然后 `node server.js`。酒馆用域名而不是 IP 访问时，用 `$env:FISH_RELAY_ORIGINS = 'http://tavern.lan:8000'` 追加允许来源（多个用逗号分隔）。未设置 `FISH_RELAY_LAN` 时中转仍只监听本机。

## 验证与接口依据

运行 `npm test` 执行本地集成测试；测试模拟网页桥接和 Fish API，不发出收费请求。覆盖音色 ID/别名/语速映射、MP3 返回、CORS 预检和访问隔离、本机与局域网的访问边界、空请求协议探测、队列顺序、取消、断线、会话鉴权、错误过滤、订阅模式不回退 API，以及 Windows 加密配置保存。

真实订阅测试记录保留在本地，不随仓库公开。

`node tools/verify-iphonie.mjs "<你的酒馆目录>\public\scripts\extensions\third-party\ST-iPhonie"` 会导入这份插件的真实请求代码，向正在运行的本机中转做空请求探测，并检查 CORS 响应；默认不生成语音。连接 Fish 后添加 `--generate` 才会生成一句短文本，消耗少量订阅额度。脚本不写插件设置，也不保存或输出 KEY。

添加 `--model=drama-3` 可以验证新版插件的 Drama 3 请求，保留当前默认模型配置。只有同时添加 `--generate` 才会实际生成。

- [Fish Audio TTS 官方接口](https://docs.fish.audio/api-reference/endpoint/openapi-v1/text-to-speech)
- [Fish Audio OpenAPI](https://docs.fish.audio/api-reference/openapi.json)
- 本机插件接入依据：`<你的酒馆目录>\public\scripts\extensions\third-party\ST-iPhonie\core\providers.js` 的 `buildRequest`、`synthesize`、`probeFish`，以及 `core/parameters.js`、`ui/engines.js` 和插件使用说明。
